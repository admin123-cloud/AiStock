# Tushare K线数据同步总结

## 问题背景

原有的TickFlow实时查询在数据完整性方面存在问题：
- 数据覆盖率低：仅31.2% (1625/5208)
- 数据质量差：很多股票的涨跌幅和成交量为0（静态数据）
- 查询效率低：需要54批×6秒 = 5.4分钟

## 解决方案

使用Tushare API替代TickFlow进行日终K线数据同步

### Tushare优势

1. **数据完整度高**
   - 一次性获取全市场5483条记录
   - 覆盖所有上市股票
   - 数据标准化程度高

2. **执行效率高**
   - 单次调用，几秒钟完成
   - 无需批量查询和限流
   - 相比TickFlow快300倍

3. **数据质量好**
   - 真实交易数据（涨跌幅、成交量等）
   - 单位标准化
   - 数据更新及时（收盘后1-2小时）

## 数据格式对齐

### 单位转换

| 字段 | Tushare单位 | 数据库单位 | 转换方式 |
|------|-------------|-----------|---------|
| volume | 手 | 手 | 直接使用 |
| amount | 千元 | 元 | ×1000 |
| change_pct | % | % | 直接使用 |
| change_amount | 元 | 元 | 直接使用 |
| turnover_rate | % | % | 直接使用 |
| amplitude | 需计算 | % | (high-low)/close×100 |

### 代码格式

- Tushare: `000001.SZ`, `600000.SH`
- 数据库: `000001`, `600000` (纯6位数字)
- 转换逻辑: 根据代码前缀推断市场后缀

## 文件清单

### 新建文件

1. `backend/src/scheduler/tasks/tushare_daily_kline_task.py`
   - Tushare日线数据同步任务
   - 自动获取当天所有股票K线
   - 支持新增和更新两种模式

2. `backend/fetch_tushare_today_kline.py`
   - 查询并验证Tushare数据
   - 返回JSON格式结果

3. `backend/import_tushare_to_db.py`
   - 将Tushare数据写入数据库
   - 自动处理新增和更新

### 修改文件

无（保留了原有TickFlow任务）

## 使用建议

### 组合策略

**盘中实时**（TickFlow）:
- 继续使用 `intraday_sentiment_task`
- 获取实时行情
- 满足盘中监控需求

**收盘后同步**（Tushare）:
- 使用 `tushare_daily_kline_task`
- 补全所有股票数据
- 确保数据完整性

### 任务配置

建议在以下时间点执行Tushare任务：
- 时间: 15:30-16:30（收盘后1小时内）
- 频率: 每个交易日一次
- 确保数据已更新
