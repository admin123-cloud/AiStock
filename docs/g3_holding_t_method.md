# G3 持仓做 T 方法（模拟执行阶段）

目标不是“每只股票每天强行交易”，而是每天无遗漏地评估每一只 QMT 持仓；只有在可验证的震荡回转条件出现时才产生一笔 T 仓计划。趋势突破、跌破风控、数据失效和涨跌停附近均不做 T。

## 固定流程

1. 每个交易日的 09:45–11:20、13:05–14:35，读取 QMT 持仓、可用股数、最新 Tick 与 5 分钟指标。
2. 数据硬门槛：账户快照必须可解析；Tick 必须在 20 秒内；价格、5 分钟 VWAP、RSI6 和盘口失衡均完整。任一项缺失即阻断，不猜测。
3. 风控优先：触发 G3 硬止损时输出 `risk_exit_no_t`，不得以做 T 名义延后退出；涨跌停附近不做 T。
4. 卖出 T 仓：仅从可卖老仓中取最多 25%，按整手向下取整。条件为价格至少高于 5 分钟 VWAP 0.6%、RSI6 不低于 70、盘口买盘失衡不低于 0.15。
5. 回补 T 仓：只能回补当日已有审计卖出记录的数量，绝不净加仓。条件为价格至少低于 5 分钟 VWAP 0.2%、RSI6 不高于 35、盘口失衡不高于 -0.10。
6. 当日每只股票最多一轮“卖 T 仓 -> 回补 T 仓”；没有回补信号则不追价。收盘前不新开 T 仓。

## 执行边界

`execution/g3_holding_t_engine.py` 只输出 `paper_sell_t_leg` / `paper_buyback_t_leg` / `observe` / `blocked` / `risk_exit_no_t`，固定 `order_path_enabled=false`。接入真实 QMT 前必须完成：逐笔模拟台账、至少覆盖不同市场状态的历史回放、滑点/手续费检验、连续纸面复现和用户显式的实盘授权。

`services/g3_holding_t_paper_monitor.py` 是可定时运行的只读接入层。它只读取已落盘的账户快照、读取 QMT 行情并将计划追加到外部 runtime 台账；不会在盘中同步账户、不会导入下单网关，也没有任何委托提交代码。账户快照不可由标准 JSON 解析时，运行会以 `broker_snapshot_invalid` 记录并停止。

使用 `scripts/install_g3_holding_t_paper_monitor_task.ps1` 可安装工作日每 5 分钟运行的纸面任务；引擎自身只在 09:45–11:20、13:05–14:35 生成评估。`-Remove` 可删除任务。任务日志位于 `runtime/g3_holding_t_paper/plans.jsonl`。
