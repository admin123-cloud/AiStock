# AiStock 系统体检与重建路线图（2026-07-26）

## 结论

系统不应整体推倒重来。现有 QMT 主链路、G3 单策略合同、影子交易保护、Docker 服务和一部分运行健康模型值得保留；但调度归属、数据闭环、核心 API 边界、遗留 G2/TDX 表面和脚本治理已经形成高风险耦合，必须按域收敛并逐步重建。

本报告只读审计，不代表已经修复或重新启动任何服务。

## 现场快照

- Docker：`aistock-frontend-dev`、`aistock-backend-dev` 均为 healthy；ClickHouse 正在运行。
- 业务健康：`/api/health/runtime` 返回 `blocked`，并且快照生成于 2026-07-24 15:00（截至审计日已过期）。日线覆盖报告仍为 `degraded`，2026-01-01 至 2026-07-24 有 1,304 个缺失 code-date、336 个不完整股票。
- 健康发布：Windows 任务 `AiStock Runtime Health Publisher` 显示 Running，最近结果 `0x800710E0`；对应 Python 进程自 2026-07-24 15:00 存活，几乎不消耗 CPU。这不是可用的健康发布闭环。
- 交易保护：当前策略合同只允许 `institutional_score120_mainwave` 产生影子交易；`auto_order_allowed=false`、`order_path_enabled=false`、`shadow_trading_enabled=true`。这一边界正确，应保留。
- 自动化：`AiStock QMT xtquant Night Rolling Repair` 最近结果为 1；日线修复任务最近结果为 0，但报告仍有缺口。因此不能把“任务返回 0”当成数据已闭环。
- 测试：32 个 pytest 用例中 31 通过、1 失败。失败于成交额快速兜底预测在收盘后返回当前成交额，未满足测试约定的“预测值应大于当前值”。
- 编码：编码守卫发现项目自有文件的 GBK/CP936 乱码和占位问号，包括 `api/system_config.py`、`frontend/src/views/g3/Gen3StateAlphaRisk.vue`、`scripts/sync_all_klines.py`；另有未跟踪的本地 `Libs/` 运行时造成大量无关噪音。

## 十个系统域的审计结论

| 域 | 当前判断 | 决策 | 首要动作 |
|---|---|---|---|
| 1. 主数据与证券主键 | QMT 接入存在；TDX 仍出现在网关、容器挂载和系统配置接口中 | 合并收敛 | 建立唯一 QMT canonical-code/板块主数据服务；TDX 仅作为显式 alias 兜底 |
| 2. 行情采集与数据质量 | 日线覆盖未闭环；分钟线有 after-close 修复链 | 重建闭环 | 用统一 coverage contract 管理日线与 5/15/30/60m，按缺口验收而非任务退出码验收 |
| 3. 数据仓库与特征 | ClickHouse 正在运行，特征口径仍分散在脚本/API 中 | 保留并收敛 | 将策略输入写成版本化特征快照，禁止页面或策略临时各算一套 |
| 4. 策略研究与回测 | `scripts/` 有 568 个 Python 文件，含 39 审计、36 回测、92 G2、261 G3 文件 | 归档重建 | 研究脚本分为正式基线、候选研究、历史归档；每项绑定数据版本和验收卡 |
| 5. 策略合同与版本 | 当前单一主策略、现金合法、G2 补位已退役 | 保留并加固 | 合同成为回测、影子、页面和风险的唯一机器可读输入 |
| 6. 盘前选股与盘中信号 | G3 信号链已存在，但核心模块过大 | 拆分重建 | 将候选生成、30m 确认、路由、票据写入独立服务，保留可追溯输入 |
| 7. 风控与组合 | 硬门槛和影子保护存在；规则分散在超大 API 中 | 拆分重建 | 风控合同独立为纯规则模块，先于信号、账户和订单执行 |
| 8. 账户与交易接入 | QMT Mini 只读快照可用，账户快照更新；订单开关关闭 | 保留隔离 | 保持 host-side QMT 读取、Docker 只读消费；下单执行留在单独隔离包，默认不可达 |
| 9. 运行编排与可观测性 | Docker 健康与业务健康脱节；Windows 任务和后端 APScheduler 并存 | 优先重建 | 每项数据/策略工件只有一个 owner、一个触发器、一个最终验证器和一个告警责任 |
| 10. 工作台与复盘界面 | G3 和 Gen2 页面同时保留；Gen2 仍有 7 个路由和对应 API | 合并收敛 | G3 四主页面为正式入口；Gen2 退为深链研究档案，禁止出现在正式交易导航 |

## 架构债务证据

1. `api/gen3_state_alpha.py` 约 14,965 行、93 个路由；`api/trading.py` 约 11,295 行、44 个路由；`api/system_config.py` 约 7,748 行、35 个路由。它们同时承担 HTTP、文件读写、调度、策略、账户和诊断，无法独立测试或安全替换。
2. `api/main.py` 在启动时同时启动核心数据调度、G2 策略刷新、G2 影子监控、V4 持仓监控和 G3 监控。这与“G3 为正式交易主线、G2 为研究/历史”的目标冲突。
3. 系统总共暴露约 280 个 HTTP 路由，正式交易面需要明显缩小；历史研究面必须改为只读且不可触发任何正式路径。
4. 根目录的 `Libs/`、`data/`、`reports/`、`Logs/`、`runtime/` 没有被 Git 跟踪，但会被全量质量检查扫描。这些目录应继续迁往外部数据/运行时路径并从工具扫描范围排除，不能纳入核心仓库。

## 重建顺序

### P0：先恢复“不可交易即不可交易”的可信判断

1. 停止把卡死的健康发布任务视作正常；查明进程阻塞点，设置单次运行超时、结构化退出码和最终快照时间门槛。
2. 修复日线 coverage 的缺口归因：上市/退市豁免、QMT 缺失、写库失败必须分型；只有 `missing_code_dates=0` 或存在正式豁免清单才可关闭。
3. 修复测试失败和项目自有文件的乱码；在 CI 前置检查中排除未跟踪的本地 `Libs/`。
4. 保持 `auto_order_allowed=false` 和 `order_path_enabled=false`，直到 P0 验收全部通过。

### P1：收敛为可维护核心

1. 建立 `market-data`、`strategy-contract`、`candidate-engine`、`risk-engine`、`broker-read-model`、`runtime-orchestrator` 六个后端域包。
2. 将 G3 正式交易 API 缩为工作台、诊断、历史复盘、风控合同四组；将 G2/API/页面迁至 `research_archive` 前缀并去掉自动调度。
3. 所有任务移到“一个领域一个 owner”模型：Windows Host 负责 QMT/xtquant；后端仅消费工件并发布只读状态；不得重复调度同一事实。

### P2：研究与界面治理

1. 将 568 个脚本登记为 `formal`、`research_only`、`historical`、`retire` 四类；未登记脚本不得被调度或从页面触发。
2. 建立策略实验注册表，回测输出必须含数据版本、成本模型、样本区间、样本外窗口和失败样本。
3. 前端只显示当前合同数据；任何英文状态码后带中文说明，并清除乱码与问号占位符。

## 阶段验收门槛

- P0 完成：业务健康快照连续稳定更新；所有工件新鲜且可解析；日线覆盖闭环；测试全绿；正式下单仍关闭。
- P1 完成：G3 正式链路不依赖 G2 调度；任意候选可追溯到数据、特征、合同和风险判定；每项运行工件只有一个 owner。
- P2 完成：脚本与页面完成分类；研究不能影响正式路径；架构、运行和策略合同文档一致。
