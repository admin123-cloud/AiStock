# 运行可视化重构与上线说明

本轮把任务执行、数据交付和主升候选拆成三个读模型。策略合同仍为代码中的 Score88 合同，QMT 主源、受控 TDX 兜底及正式下单锁保持原有规则。

## 页面与接口

| 页面 | 路径 | 主要内容 |
|---|---|---|
| 任务中心 | `/system/tasks` | Windows任务清单、API持久化状态、业务验收、异常与通知记录 |
| 数据健康 | `/data/health` | 最近10/30/60个交易日，股票/指数日线及5/15/30/60分钟覆盖，板块日线可用性 |
| 主升每日跟踪 | `/gen3/state-alpha/mainwave` | 当天结论、阻断原因、候选阶段、证据抽屉、逐日验收、同合同候选变化 |

轻量接口统一在 `/api/operations/`。GET不配置调度器、不补数、不访问交易账户、不发送消息。旧主升证据页保留在 `/gen3/state-alpha/mainwave-evidence`，新页面不在初次加载时构建全行业图表。

## 数据口径

- 交付分母来自交易日历和证券元数据，按上市/退市日期及有外部依据的业务豁免过滤；不再使用当天已经有数据的代码作为整个市场的分母。
- 分钟覆盖统计唯一代码、交易日、收盘分钟键，重复行不能抵消缺失时间键；盘中只要求已经结束的K线，不计午休和未来K线。日线16:10到期。
- 证券元数据不全可能造成待核验缺口，页面数量是当前证券池口径，不能直接等同于采集故障数量。板块尚无统一预期全集，因此只报可用数量/缺失，不显示100%。
- 覆盖齐全不代表价格、量额或主表/stage一致。G3继续使用独立的分钟来源冲突闸门，零票据也可能是数据阻断。
- 健康快照超过15分钟或时间无效即不可用于正常结论。盘后分钟报告按应交交易日定位，日线覆盖报告核对end_date；旧的成功文件不能顶替当天交付。
- 旧系统配置页的日线/分钟统计仅作样本诊断，覆盖率改为待验收，完整性以新数据健康页为准。
- 候选日期必须与摘要一致；异常和过期批次不作为每日变化的有效基线。尚无有效基线时明确显示等待记录。

## 发布器与通知

`scripts/publish_operations.py`每次读取Windows任务与数据库，写入外部runtime下的`operations/`。产物包括任务清单、交付矩阵、SQLite异常记录、每日跟踪快照和追加事件文件。所有生产补数仍由现有manifest中的唯一生产者负责；本轮没有新增第二套自动补数进程。

异常首次发现进入30分钟恢复窗口。持续超时后每轮合并为一封邮件；同一未恢复事件不重复发送已被SMTP接受的邮件，失败最多3次，每次间隔30分钟。明确的通过证据才关闭事件，某轮没有检查某项不代表已恢复。SMTP接受不等于送达/已读；SMTP调用成功后、状态落盘前若进程崩溃，可能重复发送。

仅有新发布器的近期成功心跳、通知启用且无未解决的发送故障时，G3把数据异常通知交给它；未安装、停机或发送失败则保留原G3阻断通知兜底。兜底只在原监控自身的运行窗口内生效，不能代替宿主机全天监控；整机或两个通知进程都停机时仍需要外部看门狗。

## 上线步骤

1. 保留稳态版本和现有宿主任务导出。重构开发位于独立工作树，未切换正在运行的服务。
2. 在最终部署目录核验外部路径环境变量与私有配置；不要复制真实凭证到版本控制。安装依赖并构建前端。
3. 先手动运行`python scripts/publish_operations.py`，不带`--notify`。检查任务清单、数据口径、耗时、异常归属和`operations/latest.json`。
4. 由最终部署目录运行`scripts/install_operations_publisher_task.ps1`，并明确指定正确Pythonw路径。默认安装每5分钟、单实例、2分钟执行上限的通知任务；验证时可用`-WithoutNotifications`。本轮开发没有执行安装，也没有发送测试邮件。
5. 一并更新运行健康发布器及API/前端，在合适的服务窗口切换；避免中断现有PyCharm/QMT连接。验证新任务实际运行、快照时间推进、原通知接管判断及异常重试状态。
6. 观察至少一个完整交易日和一次盘后验收，再决定继续拆分大型策略API或深入修复历史数据。超过60交易日的覆盖审计仍交给离线维护工具。

## 回滚

停止新Operations Publisher任务，恢复稳态代码与前端后重启对应服务。保留外部`operations/`作为审计记录；本轮没有数据库DDL、行情数据修改、交易参数变更或自动下单开关变更。不要删除原运行目录或外部数据目录。

## 隔离预览与验证

预览使用`api.operations_preview:app`，只注册只读接口，不运行正式API的启动生命周期。先设置`AISTOCK_DATA_ROOT`指向独立快照目录，再用Uvicorn绑定127.0.0.1:8011；前端用`VITE_API_PROXY_TARGET=http://127.0.0.1:8011`启动在3011。此预览仅支持以上三个新页面，其他业务页需在正式集成环境验收。

本轮回归覆盖：发布器过期、错误交易日、零票据分钟冲突、未解决来源空值、盘中时段、重复与缺失K线、事件去重/恢复/发送重试、通知接管失效、候选批次错配及路径变量解析。真实数据库只读验证与浏览器筛选/详情检查已经执行；390像素窄屏检查页面无整体横向溢出，1440像素宽屏检查交付矩阵。生产通知投递和实际服务切换尚未执行。前端构建存在原有大分块警告，未把这项性能优化计为完成。
